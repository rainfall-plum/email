# 管理员纯文本发送

本扩展取代原系统架构中“不提供邮件发送”的限制，保留现有收件、认证、SQLite、Postfix 和前端技术栈。没有普通用户体系、HTML 发送、附件、抄送或外部队列。

## 数据与 API

新增 `outbound_emails`，数字主键 id；字段包括 sender_mailbox_id、sender（地址快照）、recipient、subject、body_text、status、attempt_count、max_attempts、last_error、next_attempt_at、message_id、idempotency_key、created_at、updated_at、sent_at、failed_at。状态与次数有数据库约束，幂等键和 Message-ID 唯一，到期查询有组合索引。历史记录不随邮箱删除而丢失，投递前重新检查发件邮箱存在且属于配置域名。

`POST /api/outbound-emails` 必须提交 UUID idempotency_key，相同键和参数返回原任务，不重复创建；不同参数返回409。参数仅允许 sender_mailbox_id、recipient、subject、body_text、idempotency_key。主题1–200字符，正文1–100000字符，禁止空白内容、头部注入和非法控制字符。正文中的尖括号仅作为字面文本；所有邮件强制 text/plain UTF-8，不渲染 HTML。

`GET /api/outbound-emails` 支持 page、page_size（1–100）、status、sort（created_desc/created_asc）。列表不返回正文。`GET /api/outbound-emails/{id}` 返回详情。`GET /api/outbound-emails/options` 仅返回当前系统域名的已有邮箱。所有接口复用管理员认证。

`POST /api/outbound-emails/{id}/retry` 仅允许 failed 且 attempt_count < 5，原子转为 queued；不清零次数，不重发 sent，不绕过5次上限。

## Worker 与投递语义

FastAPI lifespan 启动线程，默认每2秒轮询。进程持有数据目录 outbound-worker.lock 的 OS 独占锁；退出或崩溃后锁由 OS 自动释放。多 Uvicorn 进程共享同一数据目录时仅一个 Worker 获得锁，接任者恢复遗留 sending。数据库条件 UPDATE 原子领取后提交，再进行 SMTP I/O，避免持有 SQLite 写事务等待网络。单任务异常不终止队列；数据库异常回滚并恢复可追踪状态。

通过固定的 127.0.0.1:25 投递，无 SMTP 账号或密码，socket 超时10秒。SMTP 4xx、超时、临时网络和 DNS 错误自动重试；5xx、永久 DNS 失败和无效发件人直接 failed。总计最多5次，前一次失败后分别等待60、300、900、1800秒。所有日期储存为 UTC，API 明确返回 UTC 时区。

`sent` 仅代表 Postfix 在 SMTP DATA 后接受该邮件，页面显示“已交给 Postfix”。远端邮件服务器的4xx重试、5xx退信、队列管理由 Postfix 负责；应用不会将已接受的邮件再次提交。QUIT 的错误不会被当作发送失败。

SMTP 与 SQLite 之间没有分布式事务：若 Postfix 已接受，但进程在数据库提交前崩溃，恢复后重试仍可能产生重复邮件。Message-ID 在重试中保持不变，日志标记恢复不确定性，不能承诺严格 exactly-once。不要在多个主机上共享 SQLite；同一数据库的所有进程必须使用同一个 data_dir。

## 日志、安全与部署

发送日志只含任务ID、域名、状态、次数、SMTP类别、Message-ID；异常只记录类型，不记录异常原文、SQL参数、正文或令牌。沿用 app/mail/error/access 四类 logging 输出。非预期响应采用固定友好错误。

迁移为现有 init_db / metadata.create_all 的增量建表，无删除或重写旧表。部署前使用 SQLite online backup 备份实际数据库并校验 integrity_check，随后 fast-forward pull、安装后端依赖、执行测试、前端构建、重启 email-platform。无需修改 systemd/Nginx/Postfix 配置。可设置 EMAIL_OUTBOUND_WORKER_ENABLED=false 暂停应用发送 Worker，默认启用；pytest 会关闭后台真实发送。

核查应用状态时同时核查 Postfix 按 Message-ID 关联的队列记录；外部服务器接受不等于落入收件箱。不得为排查而重复向相同测试收件人创建任务。
